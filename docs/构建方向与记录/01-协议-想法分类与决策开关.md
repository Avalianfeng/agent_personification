# 01 协议 — 想法分类与决策开关

> 目的：任何新想法（包括讨论中突然冒出来的）**不直接进实现**，先分类、放回系统、判定是否触碰已关闭决策。
> 防止「局部问题越研究越深，整个系统的依赖关系反而越来越乱」。
>
> 2026-08 增补：设计路线、外部研究优先、机制新增管线、复杂度预算、命名约定（随使用持续优化，不设死板结构）。

## 一、分类 A~G

| 分类 | 含义 | 去向 |
|------|------|------|
| A | 世界观 / 原则 | `000-认知哲学` / `006-决策-核心定位`（ADR-008） |
| B | 状态本体（状态是什么、属于谁、形态） | `03-状态本体` |
| C | 数学模型（演化、衰减、参数） | `04-状态数学` |
| D | 因果模型（事件、评价、沉积触发） | `05-事件与评价` / `06-长期沉积` |
| E | 工程实现（语言、存储、接口、CLI） | `07-工程实现` + 实现路径 |
| F | 验证（实验、判据、观测） | `08-可验证性` |
| G | Agent 适配（嘴/手/LLM 接入） | `09-嘴与手` |

**补充**：探索性/研究型想法（命名现象、领域新知、跨学科思考）→ 先入 `研究/` 区建立记录，再按需流入上述去向；机制类研究结论先进 `02-1-核心机制完备性审查`。

## 二、处理规则（三步）

1. **分类**：先归到 A~G 之一（可多选主次）；研究型想法按上节先入 `研究/`。
2. **放回系统**：看它依赖什么、影响什么（走横向轴：定义 → … → 失败怎么办）。
3. **决策开关**：判断它是否触碰**已关闭的决策**：
   - 未触碰 → 普通实现细节/新讨论项：记录到对应文件，标「待收敛 + 裁决时机」；
   - 触碰 → 明确回答：**重新打开该 ADR，还是维持原决策**。重开必须说明理由，不能悄悄偏航。

## 三、记录格式（建议）

```text
### <日期> — <想法一句话>
- 来源：…
- 现象/动机：…
- 分类：A~G｜研究
- 当前判断：已定（引用）｜开放｜待裁决
- 去向：<目标文件>；若重开决策，说明理由
```

## 四、已关闭决策速查（重开需走本节判定）

| 决策 | 状态 |
|------|------|
| 事件不直接修改状态（E → 评价 → 状态） | 已定，重开需强理由 |
| 真相层写保护（白名单：时间/评价/沉积） | 已定（ADR-002） |
| 独立内核 + 薄适配 | 已定（ADR-004） |
| 百分百可见（透明） | 已定（ADR-006） |
| Phase 1 最小优先（无探路者、不全量按规格） | 已定（ADR-007） |
| 主体性构建 = 低权重尝试，非核心目标 | 已定（ADR-008） |
| 边界划分（自建四机制+透明；借 LLM/载体/CLI） | 已定（2026-08 确认维持） |
| **四核心 = 完整内核** | **已降级**：四核心 = 四个已识别机制（第一版功能假设）；完备性待 `02-1` 审查 |
| 新增「Memory Engine」模块 | **暂缓**：记忆可能是跨时间尺度关系而非独立模块（`研究/02`）；列入审查表待研究 |

## 五、设计路线（规范流程）

```text
观察现象 → 寻找已有理论 → 提取功能 → 判断必要性 → 设计机制 → 选择数学表示 → 工程实现
```

- **寻找已有理论**不是照抄心理学，而是防「凭自我观察把容易意识到的部分当成全部因果结构」。
- 数学结构选择是**理论驱动的选择**（解释能力 / 计算成本 / 可观测性 / 可验证性），不是「简单先用，不好再换」。

## 六、外部研究优先

凡涉及「人类为什么会这样 / 机制是否真实存在 / 是否遗漏某种心理机制」→ **先查文献再设计**：

- 领域：心灵哲学 / 认知科学 / 心理学 / 神经科学 / AI·ML（continual learning 等）。
- 文献锚点与探索整理 → `研究/` 区；研究结论 → `02-1` 审查表 → 才进入机制设计。

## 七、机制新增决策管线（决定「要不要成为独立机制/模块」）

```text
现象（Phenomenon） → 功能（Function） → 机制（Mechanism） → 模块？（Module?）
```

- 最后一步才决定是否需要独立核心；多数缺口可能以「现有模块的属性/关系」解决。
- 新机制必须过复杂度预算（§八）：它引入的复杂度落在哪一层？它消除的复杂度是否大于引入的？

## 八、复杂度预算

复杂度不会凭空消失，只会转移到模型、参数、数据、计算、表示或解释层。

```text
C_total = C_state + C_dynamics + C_appraisal + C_memory
        + C_computation + C_parameterization
```

- 不问「哪个地方最简单」，问「整个系统的复杂度被放在哪里」。
- 简单状态方程 → Appraisal/沉积/参数校准承担复杂度；选型时看**全局落点**。

## 九、命名约定

- 新现象/概念一旦被识别并命名（如「信息匮乏滑坡」）→ 建立独立记录，**名称全局稳定**，正文各处引用同一名称。
- 命名格式：短横线分隔、中文为主；研究条目在 `研究/` 区（数字序号 + 短名）。
