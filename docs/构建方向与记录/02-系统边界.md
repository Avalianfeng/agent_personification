# 02 系统边界（主线 0）

> 状态：**基本已定**。此处引用已关闭决策，不再展开讨论。
> 新想法若试图扩大边界 → 走 `01-协议` 判定是否触碰已关闭决策。

## 一、边界内（内核自建）

- State Core（状态核心，真相层）
- Time Engine（时间引擎，补算）
- Appraisal（评价引擎）
- Sedimentation（沉积与反思）
- 透明轨迹（全量落迹、可回放）

## 二、边界外（借用）

- LLM 嘴/手（语言生成、行动）——借用，薄适配
- dsh / OpenClaw 等载体（验证平台）——借用，版本钉死
- CLI（基建工具，算内核的外设，非内核）

## 三、已定约束

| 约束 | 出处 |
|------|------|
| 内核独立于 LLM；拿掉 LLM 系统仍在 | ADR-004 |
| 建内核+透明，借嘴/手/验证 | ADR-005 |
| 状态与轨迹百分百可见 | ADR-006 |
| Phase 1 最小优先 | ADR-007 |

## 四、边界相关注意点

- 「借用」意味着：适配层只做翻译与回流，不承载任何状态逻辑。
- 内核不因接不接 LLM 而改变——这是接 LLM 的验收前提（见 `09-嘴与手`）。
- 待收敛项：无（边界已闭合）。若未来出现「环境/对象边界」需求（状态属于谁），归入 `03-状态本体` 九问之一，不在本文件扩界。

---

## 五、2026-08 补充：边界 ≠ 模块完备性

- 本文件只回答「**什么自建 / 什么借用**」；该边界经 2026-08 讨论**确认维持不变**——尤其 LLM 嘴/手、载体、CLI 的外部边界无问题，保留。
- 「内核内部只有四个机制」是**另一个问题**（内部功能完备性 / 功能分解），由 `02-1-核心机制完备性审查` 处理。
- ①~④ 当前的定位是**四个已识别机制**（第一版功能假设），不是已证明的完整内核；完备性待审查，之后才决定是否增删/替换/新增。
- 新想法若试图扩大边界 → 走 `01-协议` §二 判定；若试图增删内核机制 → 走 `02-1` 审查 + `01-协议` §七 机制管线。
