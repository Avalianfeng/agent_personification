# 08 可验证性 Experiments（主线 6）

> 状态：**实验框架已定**；判据量化待 Phase 1 代码前完成。
> 目的：证明「不是几个 JSON 数字在乱跳」，而是**由历史和时间产生的、可重复验证的状态系统**。

## 一、横向轴检查点（本阶段重点）

可观测量 → 验证 → 失败怎么办。每个实验都要写清三样。

## 二、实验 A~E

| 实验 | 目的 | 操作 | 预期可观测量 | 失败怎么办 |
|------|------|------|------------|-----------|
| A 时间连续性 | 状态独立于对话存在 | 关掉对话，Δt 后读状态 | 数值按衰减公式变化（容差内） | 补算或参数错误 → 查时间引擎 |
| B 事件响应 | 事件确实影响状态 | apply-event 后读状态 | 状态按评价 delta 变化 | 评价→写入链断裂 → 查 Appraisal/写白名单 |
| C 重复事件累积 | 重复痕迹有累积效应 | 相同事件重复 n 次 | 累积或按设计衰减（接沉积） | delta 钳位 / 累积规则问题 |
| D 状态恢复 / 持久化 | 状态跨进程存活 | 重启进程后读状态 | 从 state.json 恢复一致；轨迹可回放一致 | 原子写 / 持久化问题 |
| E 不同历史 → 不同状态 | 历史决定当前 | 相同初始 + 不同事件序列 | 终态可区分、可重复 | 系统对历史不敏感（马尔可夫化过头） |

> Phase 1 验收句的最小形态 = 实验 A：「关掉对话过一段时间再读状态，数值确实变了」。
