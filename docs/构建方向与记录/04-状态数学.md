# 04 状态数学 State Dynamics（主线 2）

> 状态：待收敛（开放问题 1、3）。前提：`03-状态本体` 先收敛。

## 一、数学核心

```text
S(t+Δt) = F(S_t, E_t, Δt, Θ)
```

- S_t：当前状态；E_t：Δt 内发生的事件（经评价后进入）；Δt：经过时间；Θ：系统参数。
- 完整形式（含因果位置，ADR-001 体系）：`S_{t+1} = F(S_t, E_t, Δt, C_t, A_t)`。

## 二、三个机制（自然落位）

| 机制 | 表达 | 说明 |
|------|------|------|
| 时间演化 | S_t → S_{t+Δt} | 什么都没发生，状态也在变（Time Engine） |
| 事件影响 | E →(Appraisal)→ I → S' | 事件不直接改状态，先过评价 |
| 长期沉积 | S(t) → Trace → Sediment → P | 重复痕迹形成长期特征（见 `06-长期沉积`） |

层次链：事件 → 评价 → 瞬时状态 → 时间演化 → 重复痕迹 → 沉积 → 长期人格特征。
> 定位：**人格不是 Prompt，而是历史的结果。**

## 三、成熟度定位

- Phase 1 = **L1 确定性动力系统**，推荐现形：

```text
x(t) = b + (x0 − b) · e^(−k·Δt)
```

- 不引入随机/状态空间模型，除非出现明确需求（升级规则见 `00-总览` §四）。

## 七、数学结构选择原则（2026-08 补充）

- **理论驱动选择，不是「简单先用，不好再换」**：指数衰减是**工程假设**而非理论结论，必须明确标注；选择标准：解释能力 / 计算成本 / 可观测性 / 可验证性（完整路线见 `00-总览` §一 设计路线）。
- **复杂度预算**：一处简单必有别处补偿——状态简单 → Appraisal/沉积/参数校准承担复杂度；选型看**全局复杂度落点**，不只看局部（`C_total` 思想，见 `00-总览` §一 / `01-协议` §八）。
- 若未来引入更复杂数学（L2+），必须由具体需求触发，并重新评估复杂度落点（成熟度升级规则见 `00-总览` §四）。
