# 05 事件与评价 Event / Appraisal（主线 3）

> 状态：**因果链方向已定**；评价函数具体形式待裁决（开放问题 2）。
> 这是 Phase 1 之后第一个真正复杂的地方——需要认真处理。

## 一、已定的因果链（不重谈）

```text
Event →(Appraisal)→ I（评价结果）→ S_{t+1} = F(S_t, I, Δt)
```

- **事件不直接修改状态**（关键决策，重开需强理由，见 `01-协议` §四）。
- 规则为主 + LLM 辅助（实现路径 `05-核心-评价引擎`）；评价输出为 delta + 钳位 |Δ| ≤ 0.2。

## 二、事件八问（事件建模时逐条回答）

| # | 问题 |
|---|------|
| 1 | 发生了什么？（事件类型与参数） |
| 2 | 什么时候发生？（时间戳） |
| 3 | 涉及谁？（对象绑定，取决于本体九问2 的收敛结果） |
| 4 | Agent 知道多少？（信息可得性） |
| 5 | 事件本身是否客观？（事实层） |
| 6 | Agent 如何解释？（解释层） |
| 7 | 解释产生了什么评价？（评价层） |
| 8 | 评价是否可靠？（置信度） |

## 三、为什么事件不能直接改状态（示例）

事实相同：`用户 8 小时没有回复 = NoReply(8h)`
评价可能产生：connection −2 / −0.1 / +0.5 —— 取决于上下文（关系阶段、此前事件、当前状态）。

> 这正是「事件不直接改状态」的存在理由：**同一个事实，评价必须有权给出不同结果。**
