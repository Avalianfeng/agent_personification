# 12 试验机 — 嘴层语言实验台（独立工具轨）

> 状态：**MVP 已实现**（2026-08-24）；管线设计已收敛，成果归档 `实现路径/11-工具-语言试验机`。
> 定位：独立于内核收敛主线的**工具轨**；「嘴层（LLM 语言侧）的实验室」。
> 来源：主人提出「纯 LLM 的语言操控」能力（注入 / 思考 / 多次思考 / 输出 / 加工输出 / 语言风格 / 回复模式 / 独立实验各机制）可单独优先处理。
> 分类（按 `01-协议`）：**G 主**（嘴/手/LLM 接入）+ **E 辅**（工程实现）+ **F 辅**（验证）。
> 命名：`试验机`（命名约定 §九：名称全局稳定，各处引用统一用此名）。

---

## 一、为什么单独优先（立项理由）

1. **语言层独立于状态层**：注入、思考、多次思考、输出加工、语言风格、回复模式——全是「语言进 → 语言出」管道自己的实验空间，不依赖状态数学；纯 LLM + 配置即可做，**不需要内核存在**。
2. **服务两件已挂账的事**：
   - **开放问题 4（注入格式）**：试验机就是用实验数据裁决「注入格式怎么定」的工具，不拍脑袋；
   - **Phase 2 验收项**（同一句话在不同状态下表达可区分）与防退化检查（`07-表达` §四）：试验机就是这台测量仪器。
3. **主线的基础设施，不是岔路**：管线骨架 = 未来嘴层骨架；思考/多次思考结构实验直接喂「Cognition 事件化」研究（`07-表达` §五）。
4. **工程上零阻塞**：独立小工具，语言选型不必等内核语言裁决（问题 8）；风险低、反馈快，与内核慢推演并行。

## 二、边界（是什么 / 不是什么）

| | |
|---|---|
| 是 | 嘴层的实验台：研究每个语言旋钮各自做什么；**先于内核存在** |
| 不是 | 内核的一部分（不进调用链）；不承载状态逻辑；不是产品 |
| 不触碰 | 独立内核+薄适配（ADR-004）、百分百可见（ADR-006）、Phase 1 最小优先（ADR-007）、四核心完备性（不新增内核机制） |
| 承接 | ADR-008「主体性 = 低权重尝试」：试验机里试风格/语气/回复模式都不算系统承诺 |
| 遵守 | 无状态写通道（实验不写任何状态，同 ADR-002）；全轨迹落盘（百分百可见） |

## 三、管线设计（核心）

```
输入 → [注入] → [思考×N] → [生成] → [加工] → 输出
       输入装配    思考协议    生成参数   后加工
       人格/摘要/  无/CoT/     采样参数   过滤/格式化/
       事件/指令   结构化/多轮  温度/token  润色/长度
```

- 每段**可独立开关** = 单因子实验（对应「独立实验各个机制」）；
- 每段有**可观测中间产物**（落 JSONL），轨迹可回放；
- 风格 / 回复模式：倾向定义为**跨阶段参数预设**（preset），不是独立阶段——风格主要作用于注入与生成，回复模式 = 注入方式 + 思考预算 + 加工规则的组合预设；A/B 时切换预设名即可（待收敛 R1）。

### 阶段与机制清单（第一版功能假设）

| 阶段 | 机制 | 独立开关 |
|------|------|---------|
| 注入 | 人格注入 / 状态摘要注入（先用**假摘要**）/ 事件上下文 / 指令块 | 各子项可开关 |
| 思考 | 无 / CoT / 结构化思考 / 多次思考（轮数、草稿→修订） | 模式 + 轮数 |
| 生成 | 模型、temperature、max tokens | 每项可调 |
| 加工 | 过滤（敏感/无意义）、格式化、润色、长度控制 | 可组合可开关 |
| 预设 | 风格预设、回复模式预设（跨阶段参数的命名组合） | 一键切换 |

> 注意：机制清单是**第一版功能假设**，不是完备性声明——试验中发现的新嘴层机制走 `01-协议` §七（现象→功能→机制→模块？）回流裁决，不直接堆参数。

## 四、设计原则

1. **配置即实验**：一次实验 = 一份 YAML 配置 + 一组输入；一键跑、一键重跑；
2. **可对比**：同输入 × 多配置 → 并排输出（先人工判读，需要时再加自动评估）；
3. **全轨迹**：输入、各阶段中间产物、最终输出、模型、耗时、token 数 → JSONL；
4. **不绑内核**：试验机不知道内核存在；Phase 2 时摘要渲染器（纯函数）作为注入的一个来源插进来，之前用假摘要测注入格式；
5. **无状态写通道**：实验不写任何状态；
6. **厂商无关适配**：OpenAI/Anthropic 兼容 baseURL 级 seam，模型可换（与 `docs/03` 的 seam 思路一致）。

## 五、配置示意（草案，待收敛 R2）

```yaml
experiment: style-ab-01           # 实验名（轨迹/对比文件名前缀）
input:
  text: 今天有点累
  context: 第三天对话，之前聊过工作压力
preset: reply-simple              # 可选：风格/回复模式预设
pipeline:
  inject: persona-lite            # 注入预设（可含假状态摘要）
  think: { mode: multi, rounds: 2 }
  generate: { model: gpt-4o-mini, temperature: 0.8 }
  process: [ trim, zh_soften ]    # 加工步骤列表，可空
```

## 六、横向轴检查点（每个实验必答）

- **定义**：这轮实验在动哪个旋钮？其它旋钮固定。
- **假设**：预期该旋钮如何改变输出（方向、幅度）。
- **实现**：对应 YAML 字段；一键跑。
- **可观测量**：中间产物、输出文本、token/耗时；对比差异。
- **验证**：同配置可重复（近似稳定）；单因子切换 → 差异可辨（A/B 判读）。
- **失败怎么办**：差异无法归因 → 该机制参数化不足或与其它阶段耦合 → 拆更细或承认耦合并记录。

## 七、风险与纪律

1. **吸引力陷阱**：LLM 实验反馈快、好玩。纪律：**内核轨仍是主线**，试验机轨是并行工具轨，成果独立验收——试验机的热闹 ≠ 内核的进展。
2. **反模式**：试验机自己也不堆规则——每个机制过「现象→功能→机制」管线；嘴层新机制回流系统裁决（`01-协议` §七）。
3. **过度设计**：MVP 先 CLI + YAML + 轨迹 + 手工判读；不做 UI、不做自动评估起步。
