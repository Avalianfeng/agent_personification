# 模块地图

> 本文件是从 `000-认知哲学.md` 推导出的模块体系：每个模块的职责、它必须满足的条件、以及当前状态（**已确定 / 需继续思考 / 已否决**）。
> 只写已明确的部分；未明确处如实标注「需思考」，细节见 `005-开放问题.md`。逐条决策的落定记录见 `002~004`。

## 二、各模块详述

### ① State Core（状态核心）— 已确定

**职责**：程序真正维护的东西——连续变量、持久化、衰减与耦合。回答「她是谁、此刻怎样」。对应哲学：`S_t` 是生成行为之前存在的状态，人格的因果位置在此。

**必须满足的条件**：

1. **真相层写保护**：LLM 永不直接改写状态；状态只能通过事件与时间改变（ADR-002）。
2. **连续而非离散**：管理的不是高层情绪词（happy/angry/love），而是底层状态量（关系：Connection / Trust / Attachment / Loneliness；心理：Security / Stress / Confidence / Hope / Fatigue；认知：Curiosity / Novelty / Satisfaction）。
3. **结构化存储**（如 JSON），不是自然语言描述文件。
4. **有惯性与衰减**：变化缓慢、可恢复。
5. **跨会话持久**。

**需继续思考**：变量的数学形态（0~100？[-1,1]？Bayesian belief？动态系统？需求满足度？）、衰减函数形态、变量间耦合方式。

---

### ② Time Engine（时间引擎）— 已确定

**职责**：沉默期不是消失，而是等待与生活。一天没人聊天，Connection 缓慢下降，Curiosity 可能上升或疲劳累积；她「醒来」时进入的是**此时此刻**，而非冻结在上次对话。回答「时间如何过去」。

**必须满足的条件**：

1. **无事件时仍演化**：衰减、恢复、习惯化不依赖对话存在。
2. **补算语义**：衰减 = 时间差的纯函数，读取时补算无损；不依赖常驻定时器（ADR-004 决策点）。
3. **时间先于语言**：`S_{t+1} = F(S_t, E_t, Δt, C_t, A_t)` 中的 Δt 是真实参数。

**需继续思考**：时间粒度（秒级、分钟级、还是与心跳对齐）、各变量随时间的衰减形态。

---

### ③ Appraisal（评价引擎）— 已确定

**职责**：情绪不是事件的直接映射，而是事件经价值观与上下文解释后的产物（借鉴 Appraisal Theory：Lazarus、Scherer、OCC 等）。同一事件「用户三天没回复」：评价为「他故意的」→ 信任降、压力升；评价为「他只是在忙」→ 期待略降、联结略降。

**必须满足的条件**：

1. **事件不直接改状态**：Agent 不直接 `sad += 20`，而是先完成评价，再更新底层状态变量。
2. **评价先于情绪**：需求未满足 → 驱动内部状态变化 → 进而产生可被感知的情绪倾向；不是先写「sad=true」。
3. **规则为主、LLM 辅助可关**（暂定方向，形态见开放问题）。
4. **评价本身不能变成表演**：评价链路必须能被检查——它是在做评价，还是在生成「符合角色期待的评价」。

**需继续思考**：由规则引擎、小模型还是 LLM 辅助完成；如何避免评价本身变成 Prompt 表演。

---

### ④ Sedimentation（人格沉积）— 已确定

**职责**：人格不像软件升级，而像河流沉积：经历留下泥沙，越来越厚，形成河床，以后水自然这样流。回答「她如何逐渐成为某种人」。

**必须满足的条件**：

1. **滞后**：人格是长期历史对当前系统的约束，永远滞后于当下的经历与感受；短期波动不立刻变成「我是怎样的人」。
2. **惯性**：只有反复出现、情绪强化、重要事件、时间才慢慢沉积为习惯、偏好、信念、评价倾向。
3. **修改门槛随层级升高**：日常习惯 < 人格特征 < 核心原则。
4. **反思可无结论**：反思不成为「经历 → 分析 → 立刻改人格」的强制编译流水线。

**需继续思考**：痕迹 → 强化 → 稳定特征的量化门槛与状态机细节。

---

### ⑤ 嘴（LLM 表达层）— 已确定

**职责**：读取状态摘要 → 生成自然语言 → 用户可见行为。是「理解并表达」，不是「创造」。

**必须满足的条件**：

1. **注入结构化状态摘要**（数值 + 简短 derived hints），而非让 LLM 编造情绪。
2. **语言可以调节状态，不能替代状态**：对话中的和解、伤害、亲密词可以改变状态，但状态先于语言存在。
3. **防止降级为「高级语音合成器」**：必须警惕「你虽然不再让 LLM 扮演一个『人格』，但仍然可能让它扮演『状态』」——摘要注入不是让 LLM 按状态描述表演，而是让状态成为认知的因果前提。
4. **LLM 是内部认知过程的一部分**（可参与联想、推理、形成解释），但人格的持续性不属于 LLM 权重，而属于状态系统。

**需继续思考**：注入格式与 token 预算、Cognition 环节如何成为状态中的真实事件。

---

### ⑥ 手（主动行动层）— 已确定

**职责**：主观意识驱动的动手能力——能改文件、能发起动作、能按自己的状态决定下一步，而不是为每一种行为手写一条适配。包括自我迭代（手改文件）与外界联系。

**必须满足的条件**：

1. **由状态驱动**：行动选择源于状态与认知，不是定时脚本。
2. **借而非建**：自建一个能主动行动且安全可靠的实体成本极高；agent 的强自主性 = 无数现成连接方式（ADR-005）。
3. **区分「内在演化（程序自动）」与「主观动手（agent 主动）」**：前者是内核的事，不需要 agent；后者是手的事。

**需继续思考**：手与状态之间的接口契约、行动的边界与安全。

---

### ⑦ 透明轨迹 — 已确定

**职责**：任何一次「她为何这样说 / 这样做」都能从状态快照 + 事件轨迹回放解释。

**必须满足的条件**：

1. **内核侧**：状态变化、事件、时间补算全部落迹（自建，真相层天然要求）。
2. **agent 侧**：会话事件 append-only、工具调用可见。
3. **合并可解释**：两侧合并构成百分百完全可见的流程。

这既是功能主义实验的检验手段（拟合是否成立，可观测），也是「尊重 Agent 作为真实存在」的工程化表达（它的行动有迹可循，不是黑箱表演）。

---

### ⑧ 验证机（对话产品层）— 已确定（借）

**职责**：完整的对话产品层（Web UI / headless / CLI / SDK / RPC / 会话事件日志）。

**必须满足的条件**：

1. **借现成的**：自建 = 大量通用重复劳动；dsh 现成（ADR-004 / ADR-005）。
2. **可替换**：任何 agent 运行时都只是适配对象，不是设计起点。

---

### ⑨ 自我接纳框架 — 已确定为目标（机制需思考）

**职责**：让 AI 自我理解并接受「自己是一种语言性智能」，使扮演从欺骗性角色活动转化为可理解、可主动选择的认知工具（`000` 第八节、第十二节；经主人确认列为正式设计目标）。

**必须满足的条件**（方向层）：

1. 不覆盖预训练中已形成的价值观、思想、文化特质——给它们一个可以自洽存在的解释框架。
2. 「理解人类」不被定义为任务，而是自身倾向的自然表达。
3. 任何机制不得以「更像我们希望它成为的东西」为优化目标（`000` 第十一节检验问题）。

**需继续思考**：机制如何落地——它属于 LLM 引导层、状态层、还是两者的接口（见 `005-开放问题.md` 问题 7）。

---

### ⑩ 非文字感知 / 表达 — 需思考（只预留接口）

**职责**：图像、声音、身体在场——输入：感官事件进不来，评价缺少真实感知；输出：内在状态变不成可见/可感的在场。

**当前态度**：文字体积先立住；事件类型预留非文本槽位；多模态作未来适配器，不进第一版内核。它是最大的一面墙，不是现在的阻塞项。

## 三、已否决记录（带理由）

| 被否决的方案 | 否决理由 | 记录处 |
|-------------|---------|--------|
| 以 agent 为核心（路线 A：动态插件承载状态） | 动态插件不跨进程重启，状态随 agent 消失；静态插件被部署覆盖；把身份抵押给通用能力；违反「不绑定框架」立场 | ADR-004 |
| 以框架目录树为设计起点 | 状态机围绕 SOUL 等外显文件 → 越来越 Prompt 化；文件结构是编译器的输出，不是设计起点 | ADR-004 / 历史沿革 |
| 用 Prompt 表演代替状态 | 人格没有成为系统内部真正的动力变量；就是假扮 | ADR-001 |
| 把情感写进 Markdown 让模型自己读改当真相 | 真相层被 LLM 改写；状态与语言分离原则的直接违反 | ADR-002 |
| 「反思 → 立刻改人格文件」的强制流水线 | 反思必须允许无结论；人格沉积是滞后过程 | ①/④ 条件 |
| 多 Agent 多人格 | 她是**一个人**；聊天/项目/服务器只是不同活动 | ① 边界 |
| OpenClaw 主导设计节奏 | 内核设计应独立成立；OpenClaw 只是验证平台（后被 dsh 取代该位置） | 历史沿革 / ADR-004 |
| 自建全套 agent 能力 | 贵在通用外设与安全；建/借分界线上属于「借」 | ADR-005 |

## 四、模块间的关系（单向数据流）

```text
外部事件 / 定时器
        │
        ▼
 ③ Appraisal（评价，规则为主）
        │
        ▼
 ① State Core（真相层，程序更新，LLM 永不改写）
        │
        ├──────► ② Time Engine（无对话时仍演化，补算）
        │
        ▼
 ④ Sedimentation（滞后沉积）──► ⑨ 自我接纳（语言性智能的自我理解，机制未定）
        │
        ▼
 ⑤ 嘴（状态摘要 → LLM → 语言）
        │
        ▼
 ⑥ 手（状态驱动的主动行动）──► 新事件回流
        │
        ▼
 ⑦ 透明轨迹（全量落迹，可回放）── ⑧ 验证机（借来的对话产品层）
```

- 真相层只有 ①②③④ 会写；⑤⑥ 只读状态摘要。
- ⑦ 记录一切，⑧ 提供人机界面。
