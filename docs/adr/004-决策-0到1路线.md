# 决策记录：0→1 路线

> 本文件收录「从思想到第一个可运行闭环」的路线决策。这是 ADR 体系中唯一涉及「顺序与先后」的决策，但它仍是决策而非计划——只定先后与边界，不排工期。

---

## ADR-007 0→1 路线：Phase 1 最小体积优先

- **状态**：`Accepted`（**Confirmed** —— 2026-08-16 主人当面确认）
- **日期**：2026-08-16

### 背景

当前思想存量与工程准备之间的匹配问题：要不要先走完整七维（驱动→状态→时间→评价→反思/梦境→沉积→编译）？要不要全系统 to-spec？要不要先上 wayfinder / 框架？

对谈判定：**思想够开工的是 Phase 1 最小体积，不是整条七维。**

理由核心：

- 整条七维的依赖顺序是硬性的：Sedimentation 建在长期状态之上，Compile 建在沉积之上——没有状态演化，后面一切都是空的（历史沿革中的论断：先有 State Model，才有 Time Engine → Appraisal → Sedimentation → Compiler，顺序不可倒）。
- 最小闭环能独立成立：无工具链也能「过一天、聊一句、看状态变」；它是后续一切模块的检验台。
- 不走 wayfinder：不把设计起点让给任何外部体系；不 to-spec 全系统：未决的形态问题（状态数学形态、Appraisal 实现、衰减函数）不需要在第一个闭环之前全部落定——它们恰恰应该由这个闭环来回答。

### 决策

> **先做 Phase 1 最小状态核心：三个变量、一种衰减、一个 `tick`、一个 JSON。**
> **无 LLM、无 dsh、无评价引擎。** 跑通后（关掉对话，过一段时间再读状态，数值确实变了），再以短 grill-with-docs（只烤 Phase 1 的语言、三变量、衰减形态、目录约定）收口，随后 implement。

路线边界：

| 事项 | 状态 |
|------|------|
| Phase 1：纯程序状态核心（state + time 最小集） | **本次确认，优先** |
| 短 grill-with-docs（只锁 Phase 1 口径） | 确认的下一步动作 |
| Phase 2（文本嘴）：载体改为 dsh 适配层，验收标准不变 | 后置；dsh 冒烟（headless 半天验证本地流程）后置 |
| Phase 3（评价与需求）、Phase 4（沉积与反思） | 后置；事件源来自 dsh |
| Phase 5（外设）：dsh 适配层升为默认外设 | 后置 |
| 手层接口、Appraisal 规则 vs 小模型、多模态 | 后置 / 开放 |

### 后果

- 近期唯一焦点是「一个能演示『时间流逝 → 状态变化』的纯程序」，与任何框架无关。
- 未决形态问题（变量数学形态、衰减函数、目录命名）不在开工前裁决，而由最小原型暴露后裁决。
- dsh 在 Phase 1 阶段只作可选冒烟，不进内核路径。

### 理由

- 状态的数学形态（Connection 到底是 0~100、[-1,1]、Bayesian 还是动态系统）无法靠思辨定案，需要最小原型作为讨论载体——这是「先有可跑动力学，再调参」的原则。
- 内核不被开发者预览绑架：Phase 1 无 dsh，即使用 dsh 明天发生破坏性变更，第一个闭环也不受影响。
