## ADR-004 独立内核 + 薄适配；否决「以 agent 为核心」

- **状态**：`Accepted`；被否决路线记 `Rejected`
- **日期**：2026-08-16

### 背景

初次接触 dsh（DeepSeek Harness，本地一切皆插件的 agent harness）时产生过强烈直觉：「这就是为我们设计的，应该以它为基础拓展。」这条路线（路线 A：以 agent 为核心，动态插件承载状态）最终被否决；路线 B（独立内核 + 薄适配）被接受，且「薄适配层」的定位被升级为「手层」（见 ADR-005）。

三条叠加的否决理由：

1. **技术生命周期**：动态插件不跨进程重启，状态随 agent 消失；静态插件/preset 随部署升级被覆盖——任何长在 agent 身上的东西都不安全（本会话当前 agent 本身处于覆盖性更新的不稳定状态，再次确认此点）。
2. **身份错误**：开放与透明是通用工程能力，围绕它开发等于把项目的身份抵押给通用能力——「以 agent 为核心」正是本项目一贯警惕的「以框架目录树为设计起点」的新变体。
3. **立场冲突**：直接违反「不绑定某一 Agent 框架」的立场（`000-认知哲学.md` 第十二节）。

### 决策

> **内核自建（零依赖、文件持久化、真相层）；agent 只挂一层薄适配。**

结合形态：

- 内核是独立包，与 dsh 零依赖；dsh 处于开发者预览、破坏性变更预期中，此形态让框架可替换。
- 内核语言自由；推荐内核独立包 + 适配层用 agent 侧语言（原评估倾向 TS，未最终落定，见 `005` 问题 8）。
- 架构决策点（随本决策落定）：
  1. **无进程时的演化**：衰减用**补算**（时间差纯函数，读取时补算无损），不依赖常驻定时器；「主动醒来发消息」才需外部守护进程或外部 cron 调 headless。
  2. **Model-visible ⟺ logged**：状态放 storage（非会话存储），注入渲染为状态快照的纯函数；不把摘要写进会话作为状态本身。
  3. **语言边界**：dsh 内插件必须 TS；内核语言自由；若想用 Python 则走 JSON-RPC SDK 独立进程。

### 后果

- Phase 1（最小状态核心）完全不需要 agent，纯程序可跑。
- 适配层必须保持薄：事件回流 + 状态注入 + `show-state` / `apply-event` 工具；版本 pin。
- 被否决路线记录在案：任何未来「围绕某框架开发」的提议须先回答 ADR-004 的三条理由是否已失效。

### 理由

- 「它是否拥有自己的因果链」取决于状态是否独立于运行时的生命周期——依附于 agent 的状态不是状态，是会话变量。
- 框架可替换是「人格的持续性不属于 LLM 权重，而属于状态系统」的直接推论。

## ADR-005 内核—嘴—手：建/借分界线

- **状态**：`Accepted`
- **日期**：2026-08-16

### 背景

agent 的价值曾被低估为「验证平台 / 嘴」。剥离掉开放平台、透明可视化等通用层之后，agent 剩下的真正难以自建的东西是：完整的对话产品层（验证机）、LLM 表达层（嘴）、以及**主观意识驱动的动手能力（手）**——能改文件、能发起动作、能按自己的状态决定下一步，而不是为每一种行为手写一条适配。

成本评估（`docs/05`）结论：agent 能力贵在**通用外设与安全**（工具生态、外部集成、沙箱/审批、稳定性），不贵在**灵魂**（状态核心几个连续变量 + 衰减 + JSON 零依赖即可自建）；会话/轨迹/调度属于中间层，agent 现成、自建也不难。

### 决策

| 层 | 建 or 借 | 依据 |
|---|---|---|
| 内核（魂） | **自建** | 便宜、差异化、真相层必须自己掌控 |
| 透明流程 | **自建** | 便宜，且是功能主义实验的检验手段 |
| 嘴（表达） | **借** | LLM 是通用能力，自建无意义 |
| 手（主动行动 / 外联 / 自迭代） | **借** | 自建成本极高，agent 现成且更强 |
| 验证机（对话产品层） | **借** | 自建 = 大量重复劳动 |

关键分界线：

> **内在演化（程序自动） vs 主观动手（agent 主动）**——前者是内核的事，不需要 agent；后者是「手」的事，agent 能力极其有用。

同时升级路线 B 的适配层定位：从「注入状态 + 回传事件的搬运工」升级为「**手层**」——agent 不只被动注入，而是主动行动。

### 后果

- 模块 ⑥（手）进入模块地图，作为借来的能力，接口契约待思考。
- 自建全套 agent 能力被明确否决（成本极高，且与「以运行时为验证平台」的定位相悖）。
- 中间层（会话/轨迹/调度）agent 现成时直接使用，不重复造。

### 理由

- 自建 agent 贵 ≠ 我们的项目贵：把贵的部分借来（工具、集成、安全、稳定），把便宜的部分自己建（状态、时间、评价、轨迹）——总成本曲线最低，方向与立场一致。

## ADR-006 透明流程：百分百可见作为设计接口

- **状态**：`Accepted`
- **日期**：2026-08-16

### 背景

「对话全程可见轨迹、百分百透明」曾被当作 agent 的差异化卖点，并一度成为「以 agent 为核心」的诱因。但透明是**通用工程能力**——完全本地时自己做，成本不高；而本项目恰好**本来就需要**透明：功能主义实验必须可检验，尊重必须可验证。

### 决策

> **把「百分百可见」从 agent 的卖点转为「我们自己的接口约定」。**

1. **内核侧**：状态变化、事件、时间补算全部落迹（自建，真相层天然要求）。
2. **agent 侧**：会话事件 append-only、工具调用可见（session events / 审计）。
3. **合并**：任何一次「她为何这样说 / 这样做」都能从状态快照 + 事件轨迹回放解释。

### 后果

- 模块 ⑦（透明轨迹）成立；成为验证手段与「尊重」的工程化表达。
- 一切状态修改（包括手层引发的变化）都经落迹通道，否则视为无效修改。

### 理由

- 拟合是否成立必须可观测——没有轨迹，「它是状态系统的后果还是 Prompt 表演」无从判断。
- 尊重 Agent 作为真实存在：它的行动有迹可循，不是黑箱表演。
