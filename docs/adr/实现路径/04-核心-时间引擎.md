# 04-核心-时间引擎（Time Engine）

> 状态：**已确定（补算语义）/ 待裁决（衰减函数与粒度）**
> 定位：对应 `001-模块地图.md` 模块②——「时间如何过去」；沉默期不是消失，而是等待与生活。
> 承接：ADR-004 决策点 1（补算、无常驻定时器）、`005` 问题 3。

---

## 一、职责

- 无事件时状态仍演化：衰减、恢复、习惯化不依赖对话存在；
- 她「醒来」时进入的是**此时此刻**，而非冻结在上次对话；
- 数学对象：`S_{t+1} = F(S_t, E_t, Δt, C_t, A_t)` 中的 **Δt** 是真实参数。

## 二、tick 语义（已定）

- **惰性补算**：不在后台常驻计时，而是在**读取或写入状态时**补算：
  ```
  Δt = now − state.updated_at
  对每个变量应用衰减函数 decay(var, x0, Δt)
  落迹补算（from/to/reason=补算）
  state.updated_at = now；原子写回
  ```
- **不变量**：衰减 = Δt 的纯函数；同一次补算可重复计算且结果一致（无损）。
- **理由**（ADR-004 决策点 1）：dsh `schedule` 只在 live agent 时运转；不依赖常驻定时器，内核才独立成立。

## 三、衰减函数（待裁决，`005` 问题 3）

- **候选**：
  1. **指数趋近基线**（推荐）：`x(t) = b + (x0 − b) · e^(−k·Δt)`
     - 参数：基线 `b`（恢复目标）、速率 `k`（时间常数）；
     - 行为自然：有恢复目标、不会越界、参数少、可解释；
  2. 线性：`x(t) = x0 − r·Δt`（简单，但需 clamp 且无自然趋近）；
  3. 分段/自定义（后置，原型暴露后再谈）。
- **推荐**：**指数趋近基线**。
- **决策规则**：Phase 1 grill-with-docs 裁决（连同变量集与默认参数）。

### 各变量默认参数（示例，待裁决）

| 变量 | 基线 b | 速率 k（/天） | 语义 |
|------|--------|--------------|------|
| `connection` | 0.30 | 0.05 | 联结缓慢回落（久不联系会想） |
| `fatigue` | 0.10 | 0.30 | 疲劳较快恢复（休息即恢复） |
| `curiosity` | 0.60 | 0.02 | 好奇缓慢积累→回落（无新信息时趋于基线） |

## 四、粒度（待裁决）

- **推荐**：计算按毫秒（epoch 整数），展示按天/小时；
- 备选：与心跳对齐（若未来挂 dsh schedule 再对齐）；
- 决策规则：Phase 1 裁决；默认秒级以上无感知即可。

## 五、主动醒来（已定方向，接口 Phase 2）

- 内核提供 `wake(reason)` 入口：外部守护进程 / cron / dsh schedule 调用；
- 触发条件示例（Phase 2 起）：`connection` 低于阈值、`curiosity` 高于阈值、计划性问候；
- **内核不自行常驻**（ADR-004 决策点 1）：主动醒来的调度属于外部世界。

## 六、调用顺序

```
（任意读/写入口）
   → 补算（Δt 衰减）→ 落迹 → 更新 updated_at
   → 再处理当前操作（评价新事件 / 返回快照）
```

- 关键：**先让时间流逝，再评价新事件**——评价看到的是「此刻」的状态，不是对话结束时的状态。

## 七、验收（Phase 1）

1. 关闭对话数小时/数天后，再读状态，数值按衰减函数变化（ADR-007 验收原文）；
2. 补算可重复：同一 Δt 两次补算结果一致；轨迹含 from/to/Δt；
3. 无常驻进程也能演化（纯补算）；
4. 参数（b、k）在 config 中可调，改动只影响后续演化。
