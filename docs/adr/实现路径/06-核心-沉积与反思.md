# 06-核心-沉积与反思（Sedimentation）

> 状态：**已确定（原则）/ 待裁决（量化）**
> 定位：对应 `001-模块地图.md` 模块④——人格是长期历史对当前系统的约束，滞后于当下。
> 承接：ADR-001（人格=惯性）、ADR-002（反思不写回真相）、`005` 问题 5。
> 附注：模块⑨（自我接纳）已被 ADR-008 降权，本文件不含其机制设计。

---

## 一、职责

- 人格不像软件升级，而像河流沉积：经历留下泥沙，越来越厚，形成河床，以后水自然这样流；
- 回答「她如何逐渐成为某种人」——**滞后**、**惯性**、**门槛递增**；
- 不规定「她是什么人」，规定「她是如何逐渐成为某种人的」（`000` 第十二节）。

## 二、原则（已定）

1. **滞后**：人格永远滞后于当下的经历与感受；短期波动不立刻变成「我是怎样的人」；
2. **惯性**：只有反复出现、情绪强化、重要事件、时间，才沉积为习惯、偏好、信念、评价倾向；
3. **门槛递增**：日常习惯 < 人格特征 < 核心原则；
4. **反思可无结论**：反思不成为「经历 → 分析 → 立刻改人格」的强制编译流水线（已否决记录）。

## 三、状态机（概念层，已定）

```
经历 → 痕迹 → 再次经历 → 强化 → 稳定特征 → 核心原则
         ↑                              │
         └──────── 冲突时重新解释 ───────┘
```

## 四、量化（待裁决，`005` 问题 5）

- **推荐轮廓**（Phase 4 定参数）：
  - 每个候选特征有 `strength ∈ [0,1]`；
  - 累积：事件/评价按**情绪强度 × 重复次数**计入 strength；
  - 阈值：习惯 `0.3` → 特征 `0.6` → 核心原则 `0.85`（且需跨时段证据，防单日冲高）；
  - 修改门槛随层级升高：写回特征需要更多证据事件；核心原则近乎不可改。
- **决策规则**：Phase 4 裁决；Phase 1~3 不阻塞，只预留 `sediment/` 目录与事件类型 `sediment_trace`。

## 五、数据结构（Phase 4）

```json
{
  "schema": 1,
  "updated_at": "...",
  "traits": [
    {
      "name": "tendency_to_withdraw",
      "strength": 0.45,
      "level": "habit | trait | principle",
      "evidence": ["evt-...", "evt-..."],
      "updated_at": "..."
    }
  ]
}
```

- 存放于 `sediment/sediment.json`（目录约定见 `02`）。

## 六、反思（已定方向）

- 周期性（可选）：挂 dsh `jobs` / 外部 cron；
- 产出：文学化叙述（如「信任原来长这样：不是握着，是松开后东西还在」）；
- **不写回真相状态**作为「立刻生效」的手段（ADR-002 后果）；人格变化只经沉积状态机。

## 七、验收（Phase 4）

1. 短期波动（一次冲突/一次愉快）不立刻改变特征；
2. 长期模式（重复出现、强化）才沉淀；轨迹可解释「这个特征来自哪些事件」；
3. 反思产出可无结论，且不改变状态；
4. 修改门槛随层级升高（核心原则几乎不可改）。
