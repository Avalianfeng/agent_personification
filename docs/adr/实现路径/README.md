# 实现路径 — 工程实现决策层

> 本目录是 `agent_personification` 的**工程实现决策层**：从最开始的实现到整体，按「部分 → 整体、正式使用的调用顺序」组织。
> 它是 ADR 体系的延伸：ADR `000~006` 负责「为何 / 定了什么」（立场与决策），本目录负责「**具体怎么实现**」——技术选型、数学结构、数据结构、功能接口、数据链路、验收标准。
> 每条决策遵循 ADR 体系规则：有状态、背景先于结论、后果随决策；**不排工期**，先后与边界见 `10-路线-实施顺序与验收.md`。

## 二、与 ADR 体系的关系

```
ADR 000~006（立场与决策）
   │  为什么、定了什么、开放什么
   ▼
实现路径/（工程决策层）
   怎么实现：选型 → 数据模型 → 各模块数学结构与接口 → 调用链 → 验收
```

- 约束来源：ADR-001（因果位置）、ADR-002（真相层写保护）、ADR-004（独立内核+薄适配）、ADR-005（建/借分界）、ADR-006（透明流程）、ADR-007（0→1 路线）、ADR-008（核心定位）。
- 开放问题（`005-开放问题.md`）在此逐条裁决：每裁决一条，本目录对应文件的状态从「待裁决」变为「已定」，并回写 `005`。
- 本目录允许出现「推荐 + 待裁决」形态：推荐是当前最优倾向，裁决时机在各文件「决策规则」中写明。
- 讨论过程记录在 `../构建方向与记录/`（按收敛主线 0→8 组织）；本目录为成果归档：讨论收敛一项，回写本目录对应文件并把状态从「待裁决」翻为「已定」。
