# 03-核心-状态核心（State Core）

> 状态：**已确定（职责）/ 待裁决（数学形态与最小变量集）**
> 定位：对应 `001-模块地图.md` 模块①——「她此刻怎样」的真相层。**本项目第一优先模块**。
> 承接：ADR-001（因果位置）、ADR-002（真相层写保护）、`005` 问题 1。

---

## 一、职责

- 程序真正维护的东西：连续变量、持久化、衰减与耦合；
- 回答「她是谁、此刻怎样」——状态是生成行为之前存在的因果变量（ADR-001）；
- 真相层：LLM 永不直接改写；只能通过事件与时间改变（ADR-002）。

## 二、数学形态（待裁决，`005` 问题 1）

- **候选**：
  1. 每变量 `x ∈ [0,1]` 连续标量（推荐起点）；
  2. `x ∈ [0,100]` 标量（调试直觉好，但换算多一层）；
  3. 需求满足度 / Bayesian belief / 动态系统耦合（更复杂，后置）。
- **推荐**：**`[0,1]` 连续标量** + 全局 `updated_at`。
  - 理由：简单、可读、可调参；与 delta 语义（`+0.12`）自然契合；动态系统耦合（变量间相互作用）留作后续演进，不阻塞 Phase 1。
- **决策规则**：Phase 1 原型作为讨论载体裁决（ADR-007）；裁决时同时定**默认值**与**边界行为**（clamp 或 soft bound）。

## 三、最小变量集（Phase 1，待 grill 收口）

按 `001` 模块① 的三类各取一个（推荐）：

| 变量 | 类别 | 含义 |
|------|------|------|
| `connection` | 关系 | 联结水平（对话/联结的满足度） |
| `fatigue` | 心理 | 疲劳（消耗累积） |
| `curiosity` | 认知 | 好奇（对新信息的渴求） |

- 目标：三个变量、一种衰减、一个 `tick`、一个 JSON（ADR-007 原文）。
- **决策规则**：Phase 1.5 grill-with-docs 收口（变量选择、命名、默认值）。

## 四、更新规则

```
S' = F(S, E, Δt)              ← Phase 1（无 C/A）
S' = F(S, E, Δt, C, A)        ← 完整形态（`000` 第十节）
```

- **时间**：读/写前先补算（见 `04`），Δ 来自衰减函数；
- **事件**：事件不直接改状态，经评价产出 delta（Phase 1 简化：`apply-event` 内嵌最简规则；Phase 3 起走 Appraisal）；
- **钳制**：`clamp(x, 0, 1)`；单事件 delta 上限（惯性，如 `|Δ| ≤ 0.2`，Phase 1 定值）；
- **写路径白名单**（ADR-002）：`time`（补算）、`appraisal`（评价）、`sediment`（沉积，Phase 4）；其余模块只读快照。

## 五、数据结构与函数接口

- 数据结构：见 `02-基础-存储与数据模型.md` 第二节 Schema。
- 函数接口：

| 函数 | 签名 | 说明 |
|------|------|------|
| `loadState()` | `() → State` | 读 JSON；首次无文件则按配置初始化 |
| `saveState(state)` | `(State) → void` | 原子写（临时文件 + rename） |
| `snapshot()` | `() → Readonly<State>` | 只读快照（先补算再返回） |
| `applyDelta(var, delta, source, reason)` | `(string, number, Source, string) → void` | **唯一写通道**：校验白名单与范围 → 落迹 → 更新 → 原子写回 |
| `evolve(now)` | `(number) → void` | 时间补算（调 Time Engine，见 `04`） |
| `applyEvent(event)` | `(Event) → void` | 事件入口：补算 → 评价 → applyDelta（Phase 1 简化版） |

## 六、哲学约束（不可违反）

1. **因果位置**：状态先于语言存在；任何「让 LLM 根据状态表演」的捷径都是退化（ADR-001 后果）。
2. **写保护**：LLM 的任何输出（语言、反思、手层行为）都不直接写状态；全部经程序通道（ADR-002）。
3. **不完美可接受**：状态不追求「完美拟人」，允许误判与波动（`000` 第九节、ADR-008）。

## 七、验收（Phase 1）

1. `tick` 后数值按衰减函数变化，且变化可解释（轨迹含 from/to/reason）；
2. 关闭对话（不运行任何进程），过一段时间再读，数值确实变了（ADR-007 原文验收）；
3. 全程无 LLM 参与；内核零依赖可运行；
4. 状态文件人类可读，重启后保持。
