## 二、各阶段明细

### Phase 0 — 收口（当前）

- [x] 归档旧设想 / 推进方向（已完成）
- [x] 立场、现行设想、README（已完成）
- [x] ADR 体系与核心定位（已完成，ADR-008）
- [ ] **约定仓库目录与状态文件命名（最小集）** ← 唯一剩余项，落点 `02-基础-存储与数据模型.md`
- **验收**：`02` 定稿；新代码按约定落位。

### Phase 1 — 最小状态核心（无 LLM、无 dsh，ADR-007）

- 交付：`state.json`（3 变量：connection / fatigue / curiosity）；指数衰减趋近基线（待裁决）；`tick` / `apply-event`（简化）/ `show-state`；全量落迹。
- **验收**：关掉对话，过一段时间再读状态，数值确实变了；全程无 LLM；内核零依赖。
- 待裁决项（Phase 1.5 grill 收口）：数学形态 `[0,1]`、衰减函数与参数、最小变量集、目录约定。

### Phase 1.5 — grill-with-docs

- 对象：只烤 Phase 1 的语言（若未定）、三变量、衰减形态、目录约定（ADR-007）；
- 产出：上述项裁决 → 回写 `03`/`04`/`02` 状态 → 随后 implement。

### Phase 2 — 文本嘴（载体：dsh 适配层）

- 交付：适配层（事件回流 + 状态注入 + 4 个工具，见 `08`）；摘要渲染器；`summary`/`replay`；`wake` 入口。
- 验收：不同状态下表达可区分；对话回流闭环可解释；LLM 无写路径（程序保证）。
- 附：dsh 本地 headless 冒烟（半天内，不加状态逻辑）在此阶段前或同期做（`docs/03` 近期下一步 2）。

### Phase 3 — 评价与需求

- 交付：规则表 + 校验器（delta 钳制、白名单、来源标记）；`appraisal_result` 事件；LLM 辅助开关（可关）。
- 验收：同事件不同评价 → 不同轨迹；「三天没回复」双路径可回放。

### Phase 4 — 沉积与反思

- 交付：`sediment.json`；痕迹→强化→特征状态机；阈值与门槛（0.3/0.6/0.85 轮廓，Phase 4 定）；周期性反思（挂 jobs/cron）。
- 验收：短期波动不立刻变人格；特征可溯源到事件；反思不写回真相。

### Phase 5 — 外设（可选）

- 手层接口契约升级；非文本事件槽位第一批适配（图像描述、语音转写等「降维进文字」）；自迭代（手改外显文件）。
- 验收：手能按状态主动行动，且行动全部落迹可解释。
