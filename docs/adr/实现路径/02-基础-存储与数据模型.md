# 02-基础-存储与数据模型

> 状态：**建议稿**——Phase 0 最后一项待办（目录约定）的落点；Schema 随 Phase 1 实现微调。
> 定位：数据链路的地基——文件目录、状态/事件/沉积/轨迹的结构、一致性与可回放。
> 承接：`01-基础-技术选型.md`（JSON、epoch 毫秒）、ADR-006（透明落迹）、`005` 问题 6（非文本槽位）。

## 一、目录约定（最小集，Phase 0 收口项）

```
agent_personification/
├── config/           # 配置（config.json：变量定义、参数、路径）
├── state/            # 状态真相（state.json，程序唯一写者）
├── events/           # 事件日志（append-only，JSONL）
├── sediment/         # 沉积层（sediment.json，Phase 4）
├── logs/             # 轨迹（state-changes.jsonl，append-only）
├── kernel/           # 内核代码（独立包，零依赖）
└── adapters/         # 适配层（薄；dsh 插件，TS）
```

- 命名：状态/事件文件名固定（`state.json`、`events-YYYYMM.jsonl` 分月可回放）；变量名用小写下划线。
- 约束：**状态真相只有内核程序写**；events/logs 只追加不修改（ADR-006）。
- 待确认项（Phase 0 收口时定）：是否分月分片、`sediment/` 单文件还是目录、`.gitignore` 策略（状态是否入库待议）。

## 二、状态文件 Schema（`state/state.json`）

```json
{
  "schema": 1,
  "id": "agent-001",
  "born_at": "2026-08-16T00:00:00Z",
  "updated_at": "2026-08-16T12:00:00.000Z",
  "seq": 42,
  "vars": {
    "connection": 0.62,
    "fatigue": 0.30,
    "curiosity": 0.70
  }
}
```

- `schema`：版本号，迁移入口。
- `updated_at`：**时间引擎的锚点**——所有补算的 Δt 从这里算起。
- `seq`：单调递增的事件/变化序号，轨迹回放的顺序依据。
- `vars`：连续变量，范围待 Phase 1 裁决（`[0,1]` 推荐，见 `03`）。
- 写规则：单文件**原子写**（写临时文件 → rename）；每次写前先补算（见 `04`）。

## 三、事件 Schema（`events/*.jsonl`，append-only）

```json
{
  "id": "evt-00123",
  "ts": "2026-08-16T12:00:00.000Z",
  "seq": 42,
  "type": "user_message",
  "payload": { "text": "我今天有点累" },
  "source": "dsh-session | cli | wake | tool"
}
```

### 事件类型（最小集 + 预留）

| 类型 | 含义 | 阶段 |
|------|------|------|
| `user_message` | 用户消息 | Phase 1（人手写入）/ Phase 2（dsh 回流） |
| `system_tick` | 时间推进（补算落迹用） | Phase 1 |
| `appraisal_result` | 评价产出（含 delta） | Phase 3 |
| `sediment_trace` | 沉积痕迹 | Phase 4 |
| `wake` | 主动唤醒 | Phase 2 |
| `tool_call` / `tool_result` | 手层行动（借 agent） | Phase 2+ |

### 非文本槽位（预留，不进第一版，`001` 模块⑩）

- `payload` 允许携带 `image_desc` / `audio_desc` 等**降维进文字**的字段；
- 事件类型不封闭：新增类型只追加不修改旧事件；
- 多模态进第一版**明确不做**（`005` 问题 6）。

## 四、轨迹 Schema（`logs/state-changes.jsonl`，append-only，ADR-006）

```json
{
  "ts": "2026-08-16T12:00:00.000Z",
  "seq": 42,
  "source": "time | appraisal | sediment",
  "var": "connection",
  "from": 0.65,
  "to": 0.62,
  "delta": -0.03,
  "reason": "补算：三日无对话，指数衰减",
  "event_id": "evt-00120"
}
```

- **不变量**：任何状态变化必须有对应轨迹行；否则视为无效修改（ADR-006 后果）。
- 可回放：从 `born_at` 或任意快照，按 `seq` 重放事件与变化 → 应复现当前状态（Phase 2 用 `replay` 校验）。

---

## 五、一致性策略

| 问题 | 决策 |
|------|------|
| 状态写冲突 | 单进程写（内核唯一写者）；原子 rename 防半写 |
| 事件追加 | append-only + 行级 `seq`，可恢复 |
| 补算与写回 | 读时补算（纯函数），落迹后写回；崩溃不丢因果（重放可复现） |
| 版本迁移 | `schema` 字段 + 显式迁移函数，一次只升一版 |
| 审计 | 轨迹 + 事件双日志，任何「她为何这样说/做」可回放解释（ADR-006） |

---

## 六、验收

- Phase 0 收口：目录与 Schema 文档化（本文件定稿），无歧义。
- Phase 1：`tick` / `apply-event` / `show-state` 读写一致；文件人类可读；重启后状态保持。
- Phase 2：`replay` 从事件重放 == 当前状态。
