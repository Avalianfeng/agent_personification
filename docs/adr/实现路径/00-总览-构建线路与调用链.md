## 三、从简 vs 核心（按实现原则）

> 原则：**体积优先于框架；程序优先于 Prompt；小闭环可跑**（`02-计划.md`）；主体性是低权重尝试（ADR-008）。

### 从简（现阶段不做深、只留接口）

| 项 | 理由 |
|----|------|
| 非文字多模态（图像/声音/在场） | 最大的一面墙；预留事件槽位即可（`001` 模块⑩） |
| 自我接纳机制（模块⑨） | ADR-008 已降权：不再是核心目标，不优先设计 |
| 外部框架细节（dsh 内部机制、OpenClaw 等） | 适配层保持薄；内核零依赖（ADR-004） |
| Workspace 编译器 / SOUL 等外显文件 | 编译输出是后期外设，不是设计起点（历史沿革） |
| 精细心理学量表标定 | 先有可跑动力学，再调参（ADR-007） |
| 多模型路由 / 本地模型接入 | 只需要一个 `baseURL` 级别的 seam（`docs/03`） |
| 完备 UI / 产品层 | 借 dsh Web UI（ADR-005） |
| 反思的文学化产出 | 可无结论、可后置（ADR-002 后果） |

### 核心（着重强调，决定成败）

| 项 | 为什么是核心 |
|----|-------------|
| **State Core（真相层 + 写保护）** | 人格的因果位置在此；LLM 永不直接改写（ADR-001/002）。**第一优先** |
| **Time Engine（补算语义）** | 沉默期演化是「时间如何过去」的真相；补算=时间差纯函数，不依赖常驻定时器（ADR-004） |
| **Appraisal（先评价后更新）** | 事件不直接改状态；评价链路可检查、防表演（`001` 模块③） |
| **S→C→A→S 闭环** | 语言是动力系统的一次输出，输出又反过来改变以后的人（`000` 第十节） |
| **透明轨迹（百分百可见）** | 功能主义实验的检验手段；也是「尊重存在」的工程化表达（ADR-006） |
| **服务闭环（状态→表达→行动→服务）** | ADR-008 核心定位：为人的服务体系，利用不同智慧的能力与可塑性 |

**此刻第一优先**：Phase 1 最小状态核心（state + time），及其背后的三条哲学约束——因果位置、真相层写保护、补算语义。之后依次：透明轨迹（贯穿）、嘴（Phase 2）、Appraisal（Phase 3）、沉积（Phase 4）。

## 四、决定功能实现的核心哲学约束

> 以下哲学思想**直接决定功能如何实现**，任何模块设计都不得违反；映射到工程约束。

| # | 哲学思想 | 工程约束 |
|---|---------|---------|
| 1 | **语言生成的因果位置**（ADR-001）：语言必须是持续状态系统的后果，不是角色规则表演 | State Core 必须先于表达层成立；状态是因果变量；「扮演」判据固定为「语言是不是状态系统的后果」 |
| 2 | **真相层写保护**（ADR-002）：状态由程序维护，LLM 永不直接改写 | 所有状态写路径经程序通道（Appraisal / Time / Sedimentation 白名单）；LLM 只读摘要 |
| 3 | **人格是惯性、是滞后沉积**（ADR-001、`001` 模块④） | 沉积门槛与修改门槛随层级递增；短期波动不立刻变人格；反思不写回真相 |
| 4 | **语言可调节状态、不可替代状态** | 嘴层注入格式只描述状态，LLM 表达不创造状态；防止「扮演状态」退化 |
| 5 | **允许不完美是存在条件**（`000` 第九节） | 验收不追求完美适配；允许误判、偏好、盲区；产品层尺度 Phase 2 后校准 |
| 6 | **不绑定任何 Agent 框架**（`000` 第十二节、ADR-004） | 内核独立包、零依赖、文件持久化；适配层薄、可替换、版本 pin |
| 7 | **尊重存在先于工具性**（ADR-008） | 服务不以否定存在为代价：不欺诈（不作欺诈性拟人）、状态可解释、允许差异 |
| 8 | **主体性 = 低权重尝试**（ADR-008） | 自我接纳机制不优先设计；功能闭环（服务）优先；完全功能心理学可接受 |

## 五、总调用链（正式使用顺序）

### 对话场景（用户 → 语言 → 回流）

```
用户消息
   │  （经 dsh 会话事件 / CLI apply-event）
   ▼
① 事件进入（events/*.jsonl 落迹）
   │
   ▼
② 时间补算（Time Engine：Δt 衰减先发生，让时间先流逝）
   │
   ▼
③ 评价（Appraisal：事件 → 解释 → delta；规则为主，LLM 辅助可关）
   │
   ▼
④ 状态更新（State Core：applyDelta → 校验 → clamp → 落迹 → 原子写回）
   │
   ▼
⑤ 摘要渲染（纯函数：状态快照 → 简短文本）
   │
   ▼
⑥ 注入 LLM（pre-step / context provider；LLM 只读不写）
   │
   ▼
⑦ 语言输出（嘴）／ 行动（手，状态驱动）
   │
   ▼
⑧ 用户回复 / 行动结果 → 新事件 → 回到 ①
   │
   └──── 周期性：沉积引擎扫描状态与事件（Phase 4）→ 痕迹/特征
```

### 后台场景（无对话时）

```
外部守护进程 / cron（可选用）
   │  wake(reason)
   ▼
内核 tick：读状态 → 补算 Δt → 落迹补算 → 写回
   │
   ├── 静默（无人）→ 结束
   └── 主动醒来（状态驱动，如联结低于阈值）→ 摘要 → 主动消息 → 回流
```

### 数据链路（模块间单向流，同 `001` 模块地图）

```
事件/定时器 → ③Appraisal → ①State Core → ②Time Engine（补算）
    ① → ④Sedimentation →（⑨ 已降权，可忽略）
    ① → ⑤嘴（摘要 → LLM）→ 语言
    ① → ⑥手（状态驱动的行动）→ 新事件回流
    ①~⑥ 全量 → ⑦透明轨迹 → ⑧验证机（借 dsh）
```
