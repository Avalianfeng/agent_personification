# 11-工具-语言试验机（rig）

> 状态：**已定**（MVP 已实现，2026-08-24）
> 定位：对应 `构建方向与记录/12-试验机-语言实验台.md` 的**成果归档**——独立工具轨「试验机」的工程决策。
> 承接：ADR-004（独立内核+薄适配，试验机独立于内核）、ADR-006（百分百可见，全轨迹）、ADR-008（主体性=低权重尝试，试验机是低权重尝试场所）。

---

## 一、职责与边界

- 嘴层（LLM 语言侧）的实验台：研究「语言进 → 语言出」管道里每个旋钮（注入/思考/加工/风格/回复模式）各自做什么；
- **不是内核的一部分**：不进内核调用链、不承载状态逻辑、不写任何状态（无状态写通道，同 ADR-002）；
- 先于内核存在：Phase 2 嘴层接入时，摘要渲染器（纯函数）作为注入块的一个来源插入，之前用假摘要测注入格式。

## 二、三层结构（设计核心）

```text
机制层：阶段原语 inject / think / generate / process —— 统一签名 stage_transform(stage, ctx, cfg) -> (新对象, trace)
操作层：flow 文件（显式 steps 数组，顺序可重排可重复）+ matrix 文件（axes 笛卡尔积）+ 预设（命名步骤模板）
执行层：CLI 四命令 run / matrix / compare / presets
```

- **对象模型**：messages 是主对象，text 是「最后一条 assistant 消息」的视图；inject/think/generate 吃 messages，process 吃 text——任意排列（含 generate → think → generate）无需转换胶水；
- **统一变换**：LLM 调用（provider.complete）是唯一非纯原语；mock 是确定性替身（固定假时钟 + 模板输出 + 假 usage），同配置两次运行轨迹逐字节一致；
- **预设 = 命名步骤模板**：展开成默认 steps，flow 显式项覆盖。

## 三、配置 schema

```yaml
# flow 文件
experiment: sample-demo        # 轨迹目录名
provider: mock                 # mock | openai_compat
input:
  text: 今天有点累              # 必填
  context: 第三天对话           # 可选，自动作为 system 块
preset: reply-simple           # 可选：展开成默认 steps
steps:                         # 可选：显式 steps；可只写 stage 名
  - {stage: inject, blocks: [{type: persona, ref: presets/persona-lite.yaml}]}
  - {stage: think, mode: multi, rounds: 2}     # none | cot | multi
  - {stage: generate, model: qwen2.5:7b, temperature: 0.8, max_tokens: 512}
  - {stage: process, transforms: [trim]}
```

```yaml
# matrix 文件：axes 笛卡尔积 → 组合 flow 集合
experiment: ab-test
provider: mock
input: {text: 今天有点累}
axes:
  preset: [reply-simple, style-formal]
  temperature: [0.2, 0.8]
  think: [none, {mode: multi, rounds: 2}]
```

- 注入块：persona / summary / instruction（text 或 ref 指向 YAML/md 文件）；
- 加工变换：trim / clamp_length / filter，纯函数可组合；
- 错误定位到字段路径（如 `flow.steps[0].temperature 必须是 0~2 之间的数字`）。

## 四、CLI 与运行

- `python -m rig run experiments/sample.yaml [--input 文本]`：单流程，`--input` 覆盖输入；
- `python -m rig matrix experiments/ab-test.yaml [--dry-run]`：组合批量执行，或只生成 flow 到 `experiments/generated/<实验名>/`（生成物可直接 run）；
- `python -m rig compare traces/<实验名>`：同输入多配置并排 markdown（人工判读）；
- `python -m rig presets`：列出预设。

## 五、轨迹（为 R7/嘴层衔接留余量）

- 单流程 `traces/<实验名>/<run-id>/trace.jsonl`；matrix `traces/<实验名>/combo-001/trace.jsonl` 等；
- 结构：run_start header → 步骤行 `{seq, ts, stage, cfg, obj_type, snapshot, meta}` → run_end（含配置哈希 sha256 前 12 位）；
- generate 的 meta 含 model / usage / elapsed_ms；UTF-8；`traces/`、`experiments/generated/` 入 .gitignore。

## 六、Provider

- `mock`：确定性替身，全离线可验证（默认）；
- `openai_compat`：requests 直连 `{base_url}/chat/completions`（Ollama 默认 `http://localhost:11434/v1`；Gemini 用 OpenAI 兼容端点），响应与 usage 完整落轨；
- API key 仅环境变量（默认 `OPENAI_API_KEY`，flow 可指定 `api_key_env`；`RIG_BASE_URL` / `RIG_MODEL` / `RIG_API_KEY` 可覆盖），绝不落盘。

## 七、验收（已通过冒烟）

1. mock 下同配置两次运行轨迹逐字节一致（确定性）；
2. matrix 8 组合批量执行 + dry-run 生成物可单独 run；
3. compare 并排输出可判读；
4. 非法配置报错定位到字段（temperature 越界 / 空 steps / 非法 transform / 未知阶段）；
5. 阶段排列校验：process 排在无 assistant 消息位置时报错点名步骤序号。
