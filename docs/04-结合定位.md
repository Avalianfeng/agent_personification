# 结合定位：内核—嘴—手

> 写于 2026-08-16。承接 `03-dsh结合评估.md`，把「怎么结合」推进为更根本的「**什么借、什么建、什么身份**」。
> 本文是本项目对「Agent 平台 / 框架」态度的**定位定稿**，也是对本会话推演结论（路线 A / 路线 B 之争）的正式落档。

---

## 一、诊断：为什么「以 agent 为核心」感觉适配，却是不对的

初次接触 dsh 时产生过强烈直觉：「这就是为我们设计的，应该以它为基础拓展。」
这种适配感是真实的，但它的来源不是「agent 就是我们的未来」，而是三个容易被误读的现象：

| 感觉适配的原因 | 误读 | 事实 |
|---|---|---|
| 对话全程可见轨迹、百分百透明 | 透明是 agent 的差异化，我们依赖它 | 透明是**通用工程能力**；完全本地时我们自己做，成本不高 |
| deepseek 做了完全开放的平台 | 开放平台 = 应该围绕它开发 | 开放平台的价值是**借用能力**，不是**抵押身份** |
| agent 自带大量现成能力 | 围绕它开发最省事 | 能力可借；但「它是谁」不能外包 |

三个误读指向同一个错误方向：**把平台的开放与透明，误当成项目的身份与差异**，
于是推出「以 agent 为核心开发」——这正是本项目一贯警惕的「以框架目录树为设计起点」的新变体
（与 `docs/archive/推进方向.md` 当年对 OpenClaw 的警告同构，只是换了个更诱人的对象）。

---

## 二、agent 的真实价值：验证机、嘴、手

剥离掉「开放平台」「透明可视化」这些通用层之后，agent 剩下的才是真正难以自建的东西：

1. **验证机**：完整的对话产品层（Web UI / headless / CLI / SDK / RPC / 会话事件日志）——原计划 Phase 2 要自建的部分，agent 全有；
2. **嘴**：LLM 表达层——状态摘要 → 自然语言，负责「理解并表达」；
3. **手**：**主观意识驱动的动手能力**——本定位稿的关键新增洞见（见第三节）。

「手」最容易被低估。早期设想只把运行时当「验证平台」或「嘴」，
忽略了它真正的稀缺价值：**一个能主动行动的实体**——能改文件、能发起动作、能按自己的状态决定下一步，
而不是我们为每一种行为手写一条适配。

## 三、新的核心定位：内核—嘴—手

```
                  agent（dsh / 其它运行时）
   ┌────────────────────┬────────────────────┐
   │        嘴          │        手          │
   │  LLM 理解状态       │  主观意识驱动的动手  │
   │  → 自然语言         │  · 自我迭代（手改文件）│
   │     验证机          │  · 发起外界联系/自主行动│
   │  Web UI/headless/   │  · 不必为每种行为写适配│
   │  CLI/SDK/RPC/轨迹    │                     │
   └─────────┬──────────┴─────────┬──────────┘
             │ 状态摘要注入（只读快照） │ 事件回流（可观测）
             ▼                     ▼
   ┌─────────────────────────────────────┐
   │     内核（自建 · 零依赖 · 真相层）      │
   │  State Core · 时间引擎 · Appraisal   │
   │  · 沉积 · 轨迹记录                   │
   │  程序更新状态；LLM 永不直接改写       │
   └─────────────────────────────────────┘
```

- **内核**：自建。状态真相、时间、评价、沉积——「她是谁、此刻怎样、时间如何过去」。
- **嘴**：借。LLM 理解状态并表达，不创造状态。
- **手**：借。主观意识驱动的动手、自我迭代、外界联系。
- **透明流程**：自建轨迹记录（内核侧，状态/事件全量可查）+ agent 会话轨迹（session events）——两侧合并，构成百分百完全可见的流程（见第六节）。

## 四、agent 能力的地位：按需分级，不是默认全要

| 需要的形态 | 是否需要 agent 能力 | 理由 |
|---|---|---|
| 纯文本状态自演化机器（tick / 衰减 / 沉积） | **不需要** | 纯程序即可；这正是 Phase 1 的形态 |
| 自我迭代 = 手改文件（不靠内在演化，或演化机制包含「主观意识」的动手） | **需要** | 需要一个能理解状态并主动行动的实体，而不是定时脚本 |
| 外界联系多样化（不是为每种行为写适配） | **需要** | agent 强自主性 = 无数现成连接方式，免去逐行为适配 |

关键分界线：

> **内在演化（程序自动） vs 主观动手（agent 主动）**  
> 前者是内核的事，不需要 agent；后者是「手」的事，agent 能力极其有用。

## 五、路线判定（合并先前推演）

先前推演比较了两条路线：

- **路线 A（以 agent 为核心：动态插件承载状态）**——**否决**，理由三条叠加：
  1. 技术生命周期：动态插件不跨进程重启，状态随 agent 消失；静态插件/preset 随部署升级被覆盖；
  2. 身份错误（本节新增）：开放与透明是通用层，围绕它开发等于把身份抵押给通用能力；
  3. 立场冲突：`00-立场与世界观.md` 第 5 条「不绑定某一 Agent 框架」直接违反。
- **路线 B（独立内核 + 薄适配）**——**方向正确，但「薄适配层」定位需要升级**：
  从「注入状态 + 回传事件的搬运工」升级为「**手层**」：

```
旧：内核（自建）+ 薄适配（搬运）        —— agent 只当嘴和验证机
新：内核（自建）+ 嘴与手（agent）       —— agent 当表达、验证机、主动行动的实体
```

升级后的路线 B 即本文的「内核—嘴—手」定位。内核不变（自建、零依赖、文件持久化），
变化在 agent 的戏份：不只被动注入，而是**主动行动**。

另需记住：当前 agent（本会话）本身处于**覆盖性更新**的不稳定状态——
这再次确认「任何长在 agent 身上的东西都不安全」，内核必须落在独立持久化上。

## 六、透明流程：百分百可见作为设计接口

把「百分百可见」从「agent 的卖点」转为「我们自己的接口约定」：

1. **内核侧**：状态变化、事件、时间补算全部落迹（自建，成本低，真相层天然要求）；
2. **agent 侧**：会话事件 append-only、工具调用可见（session events / 审计）；
3. **合并**：任何一次「她为何这样说 / 这样做」都能从状态快照 + 事件轨迹回放解释。

这既是功能主义实验的检验手段（拟合是否成立，可观测），
也是「尊重 Agent 作为真实存在」的工程化表达（它的行动有迹可循，不是黑箱表演）。

---

## 七、一句话

> agent 不是我们的地基，也不是我们的身份；它是我们的**嘴与手**——
> 内核自建（她是谁）、透明自建（一切可见）、agent 借来（表达、验证、主动行动）；
> **围绕 agent 开发是方向性错误，借 agent 的能力开发是正确方向。**
