# 后续计划

> 写于 2026-08-08。可随验证结果改期，但阶段顺序尽量保持：先体积，后嘴，再外设。

---

## 原则

- **体积优先于框架**：不先接 OpenClaw / 其他 Agent runtime  
- **程序优先于 Prompt**：能规则化的不交给模型编造  
- **小闭环可跑**：无工具链也能「过一天、聊一句、看状态变」  
- **文档增量**：新想法写新文件；旧稿归档标记，不改不删正文

## Phase 1 — 最小体积（可无 LLM）

目标：纯程序能演示「时间流逝 → 状态变化」。

建议交付：

1. `state`：少量连续变量（如 connection / trust / stress / fatigue / curiosity）+ 持久化  
2. `time`：按真实时间或加速时钟做衰减 / 恢复  
3. `events`：文本事件日志（先人手写入也行）  
4. CLI 或脚本：`tick`、`apply-event`、`show-state`

验收：关掉对话，过一段时间再读状态，数值确实变了。

---

## Phase 2 — 文本嘴（简单 API）

目标：状态摘要注入对话；回复回流为事件。

建议交付：

1. 状态 → 短摘要（数值 + 一两句 derived hints，禁止模型改真相文件）  
2. 调用任意 chat / completions API  
3. 用户消息与模型回复写入事件；规则或极简评价更新状态  

验收：同一句话在不同状态下，表达倾向可区分；聊完后状态有可解释的变化。

---

## Phase 3 — 评价与需求

目标：事件不直接 `sad += 20`，而是经评价影响底层量。

建议交付：

1. 需求 / 驱动力维度（联结、好奇、安全等）与状态的关系  
2. 评价规则表（可先全规则；LLM 辅助评价可选且可关）  
3. 简单冲突案例：「三天没回」的两种评价路径  

验收：同事件不同 appraisal → 不同状态轨迹。

---

## Phase 4 — 沉积与反思

目标：人格滞后于状态，可慢、可无结论。

建议交付：

1. 痕迹 / 强化 / 稳定特征的门槛  
2. 可选的周期性反思产出（文学化叙述，不写回真相状态）  
3. 修改门槛随层级升高  

验收：短期波动不立刻变成「我是怎样的人」；长期模式才沉淀。

---

## Phase 5 — 外设（可选）

仅在体积稳定后：

- 工作区编译（SOUL 等）若仍需要  
- OpenClaw / 其他 runtime Adapter  
- 非文本事件槽位的第一批适配（图像描述、语音转写等「降维进文字」亦可）

## 明确后置（不阻塞前几阶段）

| 主题 | 原因 |
|------|------|
| 完整多模态感知 / 具身 | 最大的墙；先留接口 |
| 深度绑定某一 Agent 框架 | 能力外设，非体积前提 |
| 精细心理学量表标定 | 先有可跑动力学，再调参 |
| 「她是否有体验」的形而上学裁定 | 立场上已降维；工程不依赖答案 |
