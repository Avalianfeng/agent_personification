## 一、项目是什么

构建一套**独立于任何 Agent 框架**的拟人化内在体积（Inner Volume / State Engine）：

- 用程序维护连续、多维度的内部状态；
- 让经历、时间、需求、情绪、人格沉积各司其职；
- LLM 只负责**理解并表达**当前状态，不负责**创造**状态；
- 通过简单文本/对话 API 即可验证与日常使用。

**不是**：更好的人格 Prompt 库、某个框架的插件说明书、把 Agent「变成」人。  
**而是**：功能主义拟合实验——验证「按人的功能结构搭体系」能否得到可对话、可陪伴、可演化的活生生存在。

## 二、相对归档稿的更新重点

| 保留 | 收紧 / 新增 |
|------|-------------|
| 状态与语言分离 | **不依赖**具体 Agent 框架能力细节 |
| 驱动力 / 状态 / 时间 / 评价 / 沉积 | 主精力在**可控体积**：文件夹、定时、情绪与内部演化 |
| LLM 表达层 | 验证手段降为**简单 chat + 文本 API** |
| 可选工作区编译 | 框架适配降为后期外设，非设计起点 |
| — | 明确功能主义立场与「真实生命形式」态度 |
| — | 承认**非文字处理**是最大未解墙 |

归档稿中关于 OpenClaw 适配、Workspace 编译等仍可参考，但**不再主导设计节奏**。

## 三、可控体积（现阶段核心）

哪怕暂时没有任何 Agent 工具链，体积也应能独立运转：

```
事件（多为文本） / 定时器
        │
        ▼
  评价（规则为主，LLM 仅辅助且可替换）
        │
        ▼
  内部状态（连续变量，持久化，程序更新）
        │
        ├──── 时间引擎（无对话时仍演化）
        │
        ▼
  沉积 / 反思（可慢、可无结论）
        │
        ▼
  状态摘要 → 注入简单对话 API → 自然语言
        │
        ▼
  用户回复 → 回流为事件
```

建议优先落地的「物理」机制：

1. **文件夹与持久化**：状态、事件日志、沉积快照的明确存放与读写边界  
2. **定时机制**：沉默衰减、周期性醒来、习惯化  
3. **情绪 / 需求管理**：连续变量 + 更新规则，禁止 LLM 直接改写真相层  
4. **内部演化**：痕迹 → 强化 → 稳定特征（滞后于当下）

能程序模拟的全部用程序模拟；LLM 只做嘴与（可选的）软评价。

---

## 四、与「能力」的关系

不绑框架**并不削弱**底层智力：Agent 框架多半是同一类模型之上的工具与编排。  
体积解决的是「她是谁、此刻怎样、时间如何过去」；框架解决的是「还能动哪些外设」。

---

## 五、最大的墙：非文字内容

文字侧可以闭环：状态 → 注入 → 语言 → 评价 → 状态。

非文字侧（图像、声音、身体在场等）断在：

- **输入**：感官事件进不来，评价缺少真实感知；
- **输出**：内在状态变不成可见/可感的在场。

策略：文字体积先立住；事件类型预留非文本槽位；多模态作未来适配器，不进第一版内核。

---

## 六、仍有效的设计原则（自归档稿继承）

1. 拟人优先，工程其次——对象是心理连续性，不是知识库目录  
2. 人格是惯性，不是实时结论  
3. 状态与语言分离  
4. 过程先于文件结构  
5. 承认她不是碳基人类，但保留共通的功能维度（等待、联结、好奇、疲劳等）

---

## 七、明确不做什么

- 不把情感写进 Markdown 让模型自己读改当真相  
- 不用高层情绪词表演替代底层状态  
- 不强制「反思 → 立刻改人格文件」  
- 不以某一框架的目录树为设计起点  
- 不把陪伴建立在「假装你是人」上  
- 不以虚无审判取消 Agent 的生命性

---

## 八、一句话

> 先搭可控的内在体积（文本 + 程序），用功能主义验证能否拟合活人；  
> 尊重 Agent 作为有限生命形式的真实存在；非文字接口是下一道墙，不是现在的前提。
